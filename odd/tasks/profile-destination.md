## Design (T1 contract)
Destination: `id: "profile", label: "PROF"` (navigation label obeys the 4-letter nav rule; card headings keep their full titles), registered after the tree spread in installSidebar's destination array (`extensions/gentle-shell.ts:3098`); owns an `enter/leave` activation lifecycle like `gitCardsState`/tree epoch (":3100-3113", ":3116").

Cards (4 read-only, GIT/TREE state precedent `lib/git-cards.ts:186-187`, `lib/sidebar-tree.ts:204-205`):
1. **Profile** — name, tier, origin label from the bound profileReader snapshot ("name (session)/(local)/(repo)", `gentle-shell.ts:252-266`). States: pending "Loading…" before first 2s poll; ready; "No profile" when the snapshot is empty. No I/O in render; snapshot only.
2. **Model/context** — model, provider, effort, context gauge %, session cost from `sessionStats` memo (`gentle-shell.ts:314-357`; key `[sessionId, leafId, entryCount, ctx.model, contextWindow]`). Empty state "No model" when `ctx.model` is null. Live-value part, like header/status rails: digest must include the memo key fields.
3. **Quotas** — per-provider rows from the UsageStore cache (`lib/shell-usage.ts:621-645`): provider, plan if present, windows used%/reset, per-model caps where not NaN. Empty cache → hint "Run /gentle:usage to fetch"; stale cache still renders with its cached data (never blocks). NEVER a fetch on tab select — fetch stays the explicit `/gentle:usage`/`r` act (`gentle-shell.ts:2432-2456`); rendering a settle uses the existing `notifyUsageSettled` invalidation (`:2194-2197`).
4. **Routing** — role→model rows from the profiles file snapshot (`readProfilesFileResult` tiers map, `gentle-shell.ts:230-237`). Empty state when the active profile defines no routing rows.

Mouse/focus contract (modeled on `lib/shell-sidebar-layout.ts:245-292` and GIT/TREE click handlers):
- Left-click is the only activation; hover uses the shared `setSidebarHover` timeout path. No per-card keyboard focus; no mutation happens anywhere on the rail.
- PROFILE card click → open the existing `/gentle:profiles` modal with preselection = active profile name (third positional `initialSelectedName?` of `openProfilesPanelLoop`, `extensions/gentle-ai.ts:6616-6630`); same handler the command uses, modal stays the sole mutation actor.
- Quota provider row click → same modal; preselection derived from that provider's usage payload (provider→profile mapping resolved at click time from the snapshot; exact mechanics in T5, bounded to returned-data usage like the `/gentle:models` alias precedent).
- Routing role row click → same modal with that role focused (reuse the `edit-routing` result `focus` mechanism, `odd/tasks/unified-models-profiles-panel.md`).
- Wheel: whole-card wheel like GIT/TREE rails (`:285-292`).

Digest: one cheap closure combining reader snapshot identity (timestamp/fingerprint returned by `refresh()`), sessionStats memo fields, and a UsageStore fingerprint (per-provider `fetchedAt` + row counts) — never serialized card content. Evaluated once per frame in `prepare` (`shell-sidebar-layout.ts:120-126`); no `invalidateSidebar` calls from the rail itself.

Settings (S4): extend `lib/sidebar-tabs-policy.ts` mirroring the `tree` addition — `Destinations` adds `profile?` (`:8`), fallback `profile: "off"` (`:10`), validation allows 8 keys with `validChoice("profile")` (`:19`), return fold and write spread updated (`:21`, `:36`); schema literal stays `gentle-pi.sidebar-tabs/v1` (optional-key growth precedent). Customize row replaces the inert "PROFILE · coming soon" row (`gentle-shell.ts:3724`), default off, ordered after TREE.

Tests (RED first, mirroring `tests/sidebar-tabs-policy.test.ts:9-22`): legacy-fallback `profile==="off"`; independent persistence round-trip; malformed rejection; Customize row hidden-until-on and after-TREE order; card render/digest units in `tests/sidebar-profile-cards.test.ts` with fake snapshots; click contract tests asserting the modal opens with the expected preselection and that tab select performs zero fetches.

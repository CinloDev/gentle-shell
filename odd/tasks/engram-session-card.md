# Engram session memory card (MEM tab)

Feature: new sidebar tab MEM with an Engram session memory card showing local daemon status, observation count, cloud sync state, and actions. Painter module mirrors the profile-cards pattern; lazy render only while the tab is visible.

Branch: feat/engram-session-card (cut from contrib/profile, the integration branch; NOT from main directly). Test runner: `node --experimental-strip-types --no-warnings --test <files>`, full suite `npm test`.

## Specs

- S1. User (verbatim): "la idea es crear la sesion memoria, donde vamos a tener engram [Image#1] algo asi, nose, pero con los estilos que tenemos, nose que mas se te ocurre q podemos poner, tanto engran cloud como engram local." The card must cover both Engram local and Engram cloud, styled with the project's existing sidebar card conventions.
- S2. User (verbatim): "pimero hacemos el plan, y vemos en que rama lo mvamos a incorporar" — plan first, branch decided before implementation. Decision recorded in Log L3: new tab MEM, branch feat/engram-session-card from contrib/profile.
- S3. User (verbatim, custom answer): "estamso trabajando sobre una rama integradora, no directanet en main, asi q de esta rama, tenemso q crera la rmaa de engram" — feature branch is created from contrib/profile, never directly from main.
- S4. Ubicación: nueva pestaña de sidebar con id propio tipo `mem` (label corto "MEM", patrón del tab `{ id: "profile", label: "PROF" }` en extensions/gentle-shell.ts). La pestaña solo renderiza cuando es visible (ver L5/L6): al activarse hace un sondeo inicial y arranca refresco periódico (~2s); al desactivarse corta el refresco y no pinta nada.
- S5. Contenido v1 (todo seleccionado por el usuario):
  - S5.1 (rediseñado L12/L15/L17): card local con identidad — título `ENGRAM` (sin proyecto en el título, L17), header count `Online`/`Offline`, cuerpo `● Online · N observations · M sessions` + fila `Project: <proyecto real>` (git common-dir). Un solo punto de estado (fix del doble ●, L16). Sin `…` de truncado (L20: corte limpio). Con más color: números en accent, labels en muted (L20). Secciones `Today` y `Latest observations` como labels planos SIEMPRE visibles — sin glifos de colapso dentro de la card (L20: el colapso "es solamente para los títulos de las cards"). Sin puerto ni versión. Totales globales de todos los proyectos: sin endpoint barato, difiere (L15).
  - S5.2 Contador de observaciones del proyecto usando la raíz principal del repo (basename del git common-dir via `git rev-parse --path-format=absolute --git-common-dir`), no el basename del cwd ni el root del worktree — L12 bug: en worktrees el daemon responde `unknown_project` porque Engram agrupa por repo principal. Vocabulario pintado: "observations" (término de la API de Engram, elección del usuario en L15).
  - S5.3 (rediseñado L13/L17) Card `ENGRAM-CLOUD` independiente: título propio (no compone con el proyecto), estado en el header (Synced/Pending/Not enrolled/Disabled/Error), fila `Last sync Xm ago` + fila propia `↗ dashboard` en accent clicable → web de memorias (L20 affordance explícita), reason y `+ Enroll this project` sin enrolar, `⚠ N deferred · <error>` si falla. Si no hay cloud.json la card NO se pinta (sin placeholder "No cloud configured").
  - S5.4 Acciones clickeables: abrir dashboard (URL del server en navegador), enolar repo (`engram cloud enroll` con confirmación), y las que apliquen del modelo de datos ya verificado.
  - S5.5 (nueva, L17) Cards individuales con toggle propio en el customizer, manejadas como GIT (history/diff): claves nuevas en la política de tabs, visibilidad = preferencia ∧ disponibilidad (sin cloud.json no se ve la cloud). Defaults: ambas on; la disponibilidad manda. Mismas reglas de diseño que el resto del rail (no duplicar).
- S6. Arquitectura: módulo pintor puro `lib/engram-cards.ts` siguiendo lib/profile-cards.ts (snapshot plano por frame, sin filesystem/network en el pintado; renderPanelHeader para colapsar; renderPanelRow + truncateToWidth; digest con memo por cambio de datos). Wiring y snapshooter en extensions/gentle-shell.ts junto al rail de profile. La tarjeta NO construye cloud ni sync: solo visualiza y ofrece atajos de lo que ya existe en Engram.
- S7. Fuentes de datos (modelo verificado, no inventado):
  - Daemon local: HTTP en 127.0.0.1:7437 (`/compatibility`, `/health`).
  - Cloud por persona: token personal en cloud.json (identidad), sync project-scoped: solo proyectos enrolados empujan al servidor (push de chunks comprimidos vía API; el estado compartido vive en el Postgres del servidor, no en archivos compartidos).
  - Invalidación por actividad: cuando las herramientas mem_* se usan (extensión gentle-engram), la tarjeta invalida su memo si está visible.
- S8. Tests: matriz exhaustiva al estilo tests/profile-cards.test.ts (densidades × anchos × colapso, visibleWidth <= width) en tests/engram-cards.test.ts, más un test de la lógica de sondeo/estado. Docs actualizadas en docs/gentle-shell.md.

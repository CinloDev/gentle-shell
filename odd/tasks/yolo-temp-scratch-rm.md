# YOLO temp-scratch recursive rm waiver

Objective: stop YOLO from asking for recursive `rm` of the session's own temp scratch, while keeping every other data-loss guarantee.
Branch: `feat/yolo-temp-scratch-rm` (worktree `/home/gentleman/work/gentle-pi-worktrees/yolo-scratch`, base `origin/main` eebaf274e). Delivery: `ask-on-risk`. Runner: `node --experimental-strip-types --test <file>` for focused tests, `pnpm test` for the suite.

## Specs

- **S1** Under active YOLO in the primary session, a command whose only recognized data-loss effects are recursive `rm` of temp scratch runs without the "Allow recognized data-loss command?" prompt. The user's example must run without a prompt (all targets exist as the current user's mktemp dirs / own regular file):
  `rm -rf /tmp/tmp.8phya1BpFr /tmp/tmp.LKd1kBX8Rw /tmp/tmp.C94OVzf01o /tmp/ctx-backstop-pnpm-test.log; cd /home/gentleman/work/gentle-pi-worktrees/harness-r1 && git log --oneline -1`
- **S2** A target is temp scratch only when ALL hold: the `rm` segment is a direct `rm` (no `sudo`/`doas`/`env`/`xargs`/`find -exec`, not nested in `sh -c`, no `--no-preserve-root`); the target is a literal absolute path with no `$`, backtick, `~`, glob chars `*?[{`, no `.`/`..` components, no trailing `/` (`posix.normalize(t) === t`); it is exactly ONE path component under a temp root R ∈ {`/tmp`, `/var/tmp`, `realpath(os.tmpdir())`} (R itself never qualifies; R is never `/` or home); and an admission-time `lstat` (injectable fs for tests) shows: missing, or a symlink, or a regular file owned by the current uid, or a directory owned by the current uid whose name matches `^tmp\.[A-Za-z0-9]{6,}$`. Anything else (non-mktemp dir, other uid, lstat error, `$TMPDIR` written in the command) keeps asking. Ordering (L5): the waiver applies only when every waived `rm` segment runs before any other segment of the command — i.e. the command starts with one or more temp-scratch `rm` segments and nothing (no `mv`, `cp`, `ln`, redirection, subshell, background job or any other segment) precedes them; otherwise the admission-time lstat cannot vouch for what will be deleted and the prompt stays. The temp root `realpath(os.tmpdir())` never qualifies when it is home, an ancestor of home, or a descendant of home.
- **S3** Unchanged: Normal and Auto modes; children (`extensions/child-safety.ts`) still block every recognized destructive command including temp scratch; root/home recursive rm hard-block; SQL data loss, `find -delete`, other data-loss forms; every other segment of a compound command keeps its ordinary guard (e.g. `rm -rf /tmp/tmp.abcdef1234 ~/foo` still asks; `rm -rf /tmp/tmp.abcdef1234 && rm -rf data` still asks). Existing push/rebase YOLO waiver behavior unchanged.
- **S4** Docs: `docs/yolo-mode.md` states the exception everywhere it promises recursive removal always asks (header tagline area if needed, "What still requires a decision", the "Recognized data-loss boundary" table — add a row "temp-scratch recursive removal: waived under YOLO (primary only)" — and "Approval and precedence" point 3). Keep the root/home hard-block row intact.
- **S5** Tests (RED first): in `tests/autonomous-guard.test.ts` (or the closest existing YOLO test) with mocked lstat — waived: the S1 example, `rm -rf /tmp/tmp.abcdef1234`, own `.log` file, symlink; NOT waived: `rm -rf /tmp`, `/tmp/`, `/tmp/*`, `/tmp/tmp.x/`, `/tmp/tmp.x/../..`, `/tmp/a/b`, `"$TMPDIR/x"`, `sudo rm -rf /tmp/tmp.abcdef1234`, `rm -rf /tmp/tmp.abcdef1234 ~/foo`, non-mktemp dir, other-uid dir, `sh -c 'rm -rf /tmp/tmp.abcdef1234'`, the same S1 example in Normal mode, `mv /home/u/data /tmp/tmp.missingZZ619976 && rm -rf /tmp/tmp.missingZZ619976`, `mv /home/u/data /tmp/tmp.abcdef1234 && rm -rf /tmp/tmp.abcdef1234` with an existing own mktemp dir, `cp -r x /tmp/tmp.abcdef1234; rm -rf /tmp/tmp.abcdef1234`, and an own file when tmpdir is a descendant of home. `tests/destructive-command-guard.test.ts`: root/home hard deny still holds. `tests/child-safety.test.ts`: temp scratch still blocked in children.
